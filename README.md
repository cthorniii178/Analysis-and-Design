# CS 300 Portfolio Reflection

### What was the problem you were solving in the projects for this course?

The main problem I was solving was creating a program that could help academic advisors access course information more efficiently. The program needed to load course data, organize it, print a list of Computer Science courses in alphanumeric order, and allow a user to search for a specific course and view its prerequisites.

### How did you approach the problem? Why are data structures important to understand?

I approached the problem by first comparing different data structures, including vectors, hash tables, and binary search trees. I considered the runtime and memory requirements of each structure before deciding which would work best for the program. Understanding data structures is important because the way information is stored can have a major impact on how efficiently a program can search, sort, and retrieve information.

### How did you overcome roadblocks you encountered?

One roadblock I encountered was getting the program to correctly locate and read the course data file. I eventually discovered that the data file needed to be placed in the correct directory so the program could access it. I also worked through problems by testing individual parts of the program and making corrections instead of trying to troubleshoot everything at once.

### How has this project expanded your approach to designing software and developing programs?

This project taught me to spend more time planning how information will be stored and used before beginning to code. I now better understand that choosing a data structure should be based on what the program needs to accomplish rather than simply choosing the structure that is easiest to use. Analyzing runtime also helped me think more about program efficiency.

### How has this project evolved the way you write maintainable, readable, and adaptable programs?

I have become more aware of the importance of organizing code into clear functions, using meaningful variable names, and keeping the program's logic easy to follow. Breaking a larger problem into smaller sections also makes the code easier to test and modify. These practices make programs easier for me and other developers to understand and maintain in the future.
